# Consulting knowledge and reasoning

`studio knowledge ingest --package consulting_deck_knowledge_v1` is an explicit manual batch. It checks every registered original hash, retains unknown files in place, excludes archives, evaluation content, QA caches and executable tooling from runtime retrieval. Native CSV maps, JSON contracts, JSONL chunks and topic indexes are parsed directly. Reused chunks must have unique IDs, nonempty text, resolvable source IDs and valid manual locators. PDF/MD manuals contribute page/line chunks without changing originals. TXT and JSON research provenance retain native originals and role/hash mappings rather than becoming business facts.

Canonical normalized chunks/topics/contracts and provenance/index files are immutable generations under `library/knowledge`. Global ingestion manifests commit the current generation; the package manifest view provides compatibility. A verified copy migration preserves the initial prototype generation, original paths and hashes. Unchanged reruns verify artifacts and skip extraction. Changed immutable originals or altered indexes fail explicitly. FTS retrieval has topic/kind filters, deduplicates identical text, and returns source path, hash, locator, role, and guidance-only policy. It never retrieves evaluation answers. No background watcher or automatic model ingestion is installed.

`studio reason <project> --request <project-local JSON> [--strategy model|driver]` consumes a valid `brief`, unique `coverage_keys`, verified `evidence_ids`, optional `appendix_budget`, `max_tokens`, and `analysis`. Model reasoning uses isolated no-tool inference and untrusted envelopes. Unsupported provider-schema syntax is projected for transmission; the complete local schema, including uniqueness, remains mandatory after inference.

The offline `driver` strategy requires `analysis.type=driver_diagnosis`, `attribution_status=verified_driver_contribution`, coverage `diagnosis,response`, and at least two comparable drivers with `name_evidence_id` and `impact_evidence_id`. It ranks explicitly attributed additive contributions, preserves ties, and discloses that execution feasibility and within-driver causation remain unproved. It rejects net improvement or unverified attribution. General decisions use the model strategy.

StorylineGraph contains issue/hypothesis trees, SCQA, answer-first recommendation, factual support, implications, priority, assertion titles, criteria, assumptions, tradeoffs and owner/timing next steps. MECE verifies disjoint/exhaustive sibling coverage and hierarchy/cycles. Narrative QA checks lineage/currentness, independent numeric values and units, unsupported numbers, repeated messages, topic-only titles, missing critical issue support, recommendation support and answer consistency. An executive summary is derived from actual body claims. Total main and appendix pages remain within the brief's budget; omitted detail is explicit.

Failed reasoning writes its QA result but never commits claims or a storyline. A concurrency fingerprint check prevents committing conclusions against changed evidence. Successful interpretations and recommendations enter EvidenceGraph with dependency lineage; source/guidance provenance and usage persist separately. Hypotheses remain typed, and knowledge guidance cannot substitute for project facts.

The initial controlled benchmark uses independently specified business expectations across materials-led, labor-led and tied profitability declines. Threshold: every case passes, score >=90, zero unsupported numeric claims or blocker/major narrative issues. This is a bounded first baseline; it does not claim broad industry calibration. The full consulting benchmark expands in Phase 11. Live no-tool reasoning smoke is separate from deterministic regression.
