# Independent Critic and contextual preference learning

`studio review PROJECT --spec SPEC --render-report REPORT --output OUTPUT` reviews the exact candidate/canonical hash against its genuine native render proof. The isolated Critic receives the brief, public IR, independently read raw/calculated facts, candidate claim lineage, rendered images/native metrics and reference intent. It does not receive Builder rationale or logs. The configured model runs in a fresh ephemeral no-tool context with source images copied into a bounded inference job; every slide and finding target is schema-checked. Consulting guidance comes from the same provenance-aware knowledge store as reasoning, with evaluation material excluded.

The configurable seven-dimension rubric covers content accuracy, narrative clarity, hierarchy, layout integrity, brand fit, editability and source integrity. Default threshold is 90; message scores below 85 fail the affected slide. Canonical BLOCKER/MAJOR/MINOR/STYLE findings carry actual target IDs, evidence references and repair intent. Blockers and major findings fail regardless of aggregate score. Independent quantitative-copy/source/native-data checks cannot be overridden by a perfect model score.

Native smoke exposed overconfident additivity language in the offline driver strategy. It now treats non-overlapping additivity as a condition before aggregation and avoids implying favorable offsets when none are supplied. Unit wording uses a grammatical singular for one point while retaining the exact declared evidence unit. Native text is wrapped using installed glyph advances with a conservative line margin; native QA remains the final authority, and font/overflow thresholds are unchanged.

`studio feedback --request REQUEST.json` records text, pattern, optional event ID and user/project/brand context. Intent classification separates design/copy preferences from factual corrections, data updates, requirements, scope and brand changes. A numeric factual correction stays preference-neutral even if mislabeled as design rejection. Explicit signals have modest Bayesian shrinkage; implicit selection/reuse/redesign/removal signals have at most 0.25 strength. Silence alone is not an approval event.

Immutable event identities reject conflicting replay. Derived preference state tracks positive/negative/neutral/deprecated events, sample counts, tags, dimensions, confidence strength and recency decay. Reset rules establish a temporal cutoff while preserving audit events; subsequent observations can learn again. Explicit overrides are contextual and bounded to -1..1. Use `studio preferences status|reset|override` to inspect/control them.

Eligible automatic layouts and reference candidates can be reranked from preference state. This never changes factual values, binding provenance, explicit requested archetypes or readability constraints. Reference approval learns only when invoked as a genuine user promotion, and evaluation fixture approvals remain isolated. Rejected/deprecated examples are retained and downranked rather than deleted.
