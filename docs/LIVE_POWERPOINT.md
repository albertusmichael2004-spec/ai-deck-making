# Live PowerPoint collaboration

Use `studio live attach PROJECT` for the selected canonical with save_existing. The CLI opens that same existing working target if needed, reusing the running application or starting PowerPoint when absent. `--require-open` disables automatic opening; `--target ... --save-policy manual` selects an explicit project working target and deliberately retains unsaved revisions. The backend never quits a borrowed application. Target matching uses exact local identity, including Office OneDrive URLs mapped through registered Windows sync roots; file-name guesses are rejected. Only that project's PPTX working files can be mutated; project inputs are rejected before writable native opening.

`live inspect`, `selection`, `comments`, `plan-comments`, `apply-comments`, `apply`, `save`, `recover` and `detach` operate on that session. Use `--output PROJECT/work/selection.json` to retain a captured selection. Revisions take `--request` JSON containing `patch`, `scope`, `spec` and optional `selection`. Comment planning takes `scope`; applying a persisted plan takes `plan` and `spec`. Author/slide filters and explicit `--combine-selection` are supported. Selection does not silently broaden scope.

The open in-memory presentation is authoritative. SaveCopyAs captures unsaved content without replacing the original. Native planned and applied renders use a separate readonly presentation copy in the existing application, closing only that copy. Every mutation requires matching live generation and target fingerprints, and both deterministic QA and an isolated image-capable Critic must pass. Project file writers remain excluded while live authority is active.

Save policy is explicit: `manual` retains unsaved changes, `save_copy` writes a new named copy while preserving original dirty state, and `save_existing` saves only after review and a matching disk fingerprint. Windows shared-read hashing respects existing file locks. If a cloud lock makes a verified fingerprint unavailable, save-existing fails closed while manual/copy modes remain available. AutoSave is paused during mutation and post-apply QA so cloud saving cannot bypass the gate. It is restored only when the presentation is saved; manual unsaved work keeps it paused until an explicit save decision. These behaviors follow the native [SaveCopyAs](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentation.savecopyas) and [AutoSaveOn](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentation.autosaveon) contracts.

Comments are untrusted scoped presentation instructions. Current SaveCopyAs snapshots are read for both legacy comments and [modern comment threads](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/af0dc8d7-ee58-435b-80fb-72f2b351b689), including replies and actual Office author metadata. Positional containment, object type, text overlap and optional selection determine target confidence. Ambiguous, conflicting or policy-changing comments remain blocked; original comments are preserved. CommentLedger stores discovered/planned/applied/blocked/ambiguous/ignored states and transaction references for idempotent scans. Genuine design/copy feedback may update preferences; numerical corrections remain neutral. Reply capability is feature-detected rather than assumed.

Live transaction journals retain the before snapshot, candidate, planned/applied render and review reports, scope, operation intent and owned changes. Recovery never uses Undo as its sole mechanism. It restores only targets whose current fingerprint still matches the agent's recorded mutation; later user changes and interrupted unknown partial writes are preserved with a recovery conflict and snapshot. Detach does not close the presentation; an unsaved canonical target must first be saved or closed safely. COM STA lifetime belongs to the terminal, so releasing borrowed proxies does not tear down other callers' Office objects.

When a style requires file-mode revision, save/release live authority and use the same managed canonical through the [target update workflow](TARGET_UPDATES.md). Do not create another working deck as a fallback. Native QA can borrow a running application, and project commit can safely refresh the exact open target after validation. An unsaved selection never silently becomes whole-object or whole-deck scope.

Each CLI live command uses a separate worker with a configured deadline. Timeout terminates only that worker, preserving PowerPoint and durable recovery state. Unresolved applying/recovery/conflict journals block further mutation, saving and authority release. Reopen a saved target explicitly with `--open-if-missing` before reconciling a closed session; the system cannot reconstruct unsaved work that a user discarded when closing PowerPoint.

Native integration fixtures use owned minimized presentations and actual PowerPoint capture/render/mutation. Fault and concurrency tests deliberately control the reviewer to inject interruptions; those scores are not quality evidence. The separate `scripts/live_model_smoke.py` requires real isolated image-capable model reviews before and after mutation, records measured token usage, and persists both native QA reports. Release gates require both classes of evidence.
