# Release hardening and measured benchmark evidence

Require actual isolated visual review for quality, independently verified source/number checks and native integration evidence. Controlled fault injection verifies transactions without treating artificial perfect reviewer scores as quality proof. Full-system synthetic cases cover three industries, tied priorities and negative offsets. Failed attempts remain auditable; accepted cases are reused only if their source/canonical hashes still match.

The retail release case exposed unclear distinction between cited contribution data and proposed operating actions. New recommendation messages explicitly identify proposed actions; the accepted retail deck received a narrow body patch, preserving all numbers, source notes and other objects. Its stricter grounding threshold was not relaxed. The financial-services case exposed sign loss in narrative numeric-token parsing; preserve signed literals and reject inverted signs.

Missing registered visible citations now independently block QA even when qualitative scores are perfect. Interrupted live mutations cannot be saved or released before recovery is resolved. Live CLI calls use terminal-owned bounded processes; timeout never kills Office. Owned test fixtures release child proxies while native objects remain alive before closing their private presentation/application.

Provider telemetry records measured input/output/cached tokens and latency without hidden reasoning. Unknown monetary cost remains null in release reports; monetary-budget requests require a priced adapter. Installation smoke is explicitly an isolated editable environment reusing verified local dependencies, not a fresh network dependency-resolution claim.
