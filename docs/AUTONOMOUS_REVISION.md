# Autonomous revision

`studio run PROJECT --request PROJECT/work/request.json` prepares supplied sources, optional factual research, verified reasoning and consulting design, then executes the native build/render/deterministic-QA/isolated-Critic/repair/commit loop. Requests contain `brief`, `sources` (path plus optional units/period), optional `research`, `reasoning` (coverage keys, selected evidence, model or verified driver strategy), optional `exhibit_intents`, `scope` and `budgets`. Research must be complete before analytical handoff. Existing lower-level commands remain available.

The loop defaults to at most three repairs, 192,000 measured tokens and 900 seconds. Optional monetary limits require provider cost telemetry; unknown cost cannot count as zero. Time/token/cost exhaustion, no-op repairs, diminishing improvement or tool limitations stop without committing. Every review uses an exact candidate hash and genuine native renders, with fresh independent evidence checks. BLOCKER/MAJOR findings cannot be overridden by a score.

Each run persists `work/offline_runs/<run_id>/run.json`, immutable candidates and declared specs per iteration, scoped PatchPlans and complete render/QA/Critic reports. Resume with `--resume <run_id>` only accepts identical request intent, unchanged canonical generation and matching evidence/candidate hashes. Orphan candidates from an interrupted pointer update are safely ignored. Committed replay is a no-op; a later user edit causes a conflict. Project transaction recovery handles an interrupted atomic commit.

Programmatic `OfflineLoop.run` supports existing decks through `initial_patch` or `previous_spec` plus `changed_evidence_ids`, always with explicit trusted scope. Whole-deck replacement is rejected. RepairPlanner orders findings BLOCKER, MAJOR, MINOR, STYLE, requests tool-free structured operations and never executes source instructions. PatchExecutor verifies target fingerprints and scope, preserves untouched package payloads and rejects new unsupported numerical copy. Source notes remain generated from registered provenance.

IncrementalCompiler computes slide consumers from claim/binding dependencies, prepares only affected layouts and imports their dependency closures under collision-free names. Existing masters, media and untouched slide payloads remain byte-identical. Analytical source refresh recomputes calculated facts and marks interpretations/recommendations stale. Such claims require regenerated, narrative-validated current reasoning before affected exhibits can compile. Every resulting deck still receives full native rendering and protected-object/data regression checks before commit.

`AnalyticalRefresh.prepare` performs source refresh, fresh evidence-grounded reasoning and narrative validation, then rebinds the updated exhibits/claims to stable slide and deck identities. Old claims remain stale for audit. A changed page count or purpose sequence requires a structural revision scope. Pass the returned spec and changed evidence IDs to `OfflineLoop.run(previous_spec=..., scope=...)` for incremental compilation and complete post-refresh review.

PatchSpec 1.1 adds a narrow `repair_chart_axis` operation with value `zero_origin`. It corrects horizontal bar crossings without modifying values, labels or workbooks. Chart fingerprints include dependency payloads; deterministic exhibit QA rejects a nonzero or truncated bar origin. The source/candidate hash and all protected objects still apply.
